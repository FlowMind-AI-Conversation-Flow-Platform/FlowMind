# FlowMind QA Gate

## 목적
변경사항을 배포 가능한 수준으로 검증하고 잔여 리스크를 명확히 한다.

## 실행 절차
1. 변경 범위 기반으로 검증 계획을 만든다.
2. 가능한 자동 검증을 우선 실행한다.
- 단위/통합 테스트
- 핵심 엔드포인트 smoke 체크
3. 실패를 재현 가능한 형태로 기록한다.
4. 결과를 `통과/실패/미검증`으로 분류한다.

## 검증 원칙
- 존재 확인이 아닌 계약 검증을 수행한다.
- 입력/출력 shape, 상태코드, 설정값 영향도를 함께 본다.
- 실행하지 못한 검증은 이유를 기록한다.

## 체크리스트
- [ ] 재현 명령이 포함되어 있는가
- [ ] 실패 원인이 추정이 아닌 근거 기반인가
- [ ] 회귀 가능 영역이 명시되었는가
- [ ] 미검증 항목이 분리되어 있는가
