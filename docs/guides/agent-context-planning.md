# Agent Context: Planning and Approval

## 목적

이 문서는 FlowMind 프로젝트에서 에이전트가 계획을 세우고 사용자 승인을 받은 뒤 작업을 진행하는 절차를 상세화한다.

## 승인 전 허용 범위

승인 전에는 아래만 가능하다.

- 저장소 구조 탐색
- 관련 문서 읽기
- 현재 상태 분석
- 위험 요소 식별
- 작업 계획 작성

승인 전에는 아래를 하지 않는다.

- 파일 생성
- 파일 수정
- 파일 삭제
- 의존성 추가
- 구조 변경

## 계획 작성 형식

계획에는 아래 항목을 포함한다.

### 1. 목표

- 이번 작업에서 해결하려는 문제

### 2. 변경 범위

- 어떤 계층을 건드리는지
- 어떤 기능까지 포함하는지
- 무엇은 이번 범위에서 제외하는지

### 3. 예상 파일

- 생성될 파일
- 수정될 파일
- 읽기만 할 파일

### 4. 위험 요소

- 기존 설계와 충돌 가능성
- 데이터 모델 영향
- 문서와 구현 불일치 가능성

### 5. 검증 방법

- 어떤 명령이나 테스트로 확인할지
- 직접 실행이 불가능하면 무엇으로 대체할지

## 승인 요청 문구 원칙

승인 요청은 짧고 구체적이어야 한다.

반드시 포함할 것:

- 무엇을 바꾸는가
- 왜 필요한가
- 어떤 파일이 바뀌는가
- 어떻게 검증하는가

## 작업 중 재승인이 필요한 경우

아래 상황에서는 다시 승인받는다.

- 계획에 없던 파일 수정이 필요한 경우
- 설계 방향이 바뀌는 경우
- 스키마나 의존성 추가가 필요한 경우
- 예상보다 작업 범위가 커지는 경우

현재 기준 예시:

- `Phase 2` 작업 중 `OpenAI SDK`까지 넣으려면 재승인 대상
- 단순 문서 최신화에서 execution plan 이동까지 포함되면 범위 재확인 권장

## 권장 작업 단위

작업 단위는 가능한 한 작게 유지한다.

좋은 예:

- dispatch API 스펙 정의
- billing inquiry 시나리오 1개 구현
- LLM gateway 추가
- Phase 상태 문서 최신화

좋지 않은 예:

- 전체 플랫폼 구현
- 프론트/백엔드/DB/LLM 전부 한 번에 수정

## 작업 완료 보고 형식

완료 보고에는 아래를 포함한다.

- 실제 변경 내용
- 검증 내용
- 미완료 또는 보류 항목
- 다음 단계 제안
